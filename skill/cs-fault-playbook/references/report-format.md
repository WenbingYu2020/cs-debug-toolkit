# 报告格式（标准 v1，MD + HTML 双写）

> **单一出处**：`docs/REPORT_STANDARD.md` §3（MD 五段）/ §4（HTML 十区块）/ §5（落盘与结案清理）/ §6（自检清单）。
> 本文件是技能内的**执行摘要**；与 `docs/REPORT_STANDARD.md` 冲突时以后者为准。
> 定标样本：2026-09-25「<渠道> · <店铺> / <客服账号> — <问题简称>」标准格式报告。

## 交付物（缺一不合格）

| 文件 | 命名 | 位置 |
|---|---|---|
| Markdown 最终报告 | `<YYYYMMDD>-<渠道>-<账号简称>-<问题简称>_FINAL_REPORT.md` | 交付目录根 |
| 单文件自包含 HTML | `<YYYYMMDD>-<渠道>-<账号简称>-<问题简称>_report.html` | 同上 |
| 辅助佐证报告（如有） | `<YYYYMMDD>-<主题>_<类型>报告.md` | 同上 |
| 截图（唯一留存物） | — | `<交付目录>\证据区\screenshots\` |

**交付目录**：本机 cs-cli 环境 = `D:\temp\<客服账号名>\`（先校验存在性，不存在才建）；外部分发包环境 = `<输出目录>`（`~/.csdbg/temp` 或 `<TOOLKIT>/temp`）。

## MD 五段（固定）

1. **标题 + 元信息**：`# YYYY-MM-DD 渠道·店铺 / 客服账号 —— 一句话问题（进行中/已恢复）`；引用块写时间基准（北京时间）、严重度·影响、排查方式·排查时间。
2. **一、问题描述**：`项 | 值` 表——渠道 / 店铺 / 客服账号 / 设备 ID（32 位）/ 主机名·云桌面 / RPA 版本（含变更时点）/ workspace·agent（32 位）/ 报障时间（含来源）/ **实际故障窗口（精确到秒）** / 用户原话 / 技术转述。
3. **二、最终结论报告**：一句话结论（已证范围内）→ **关键 ID 清单**（设备/主机/受影响会话/受影响但无记录）→ **A. 已证**（`E1…En`，每条挂来源+时间戳+原文）→ **B. 未证候选**（解释力/张力/判别方法）→ **C. 判别性检查清单**（看什么·在哪看·判定）→ **D. 六源定责**（服务端→agent→RPA→host/IP→渠道平台→运维服务；`R0 主责/R1 次责/R2 待定/R3 无责`）。
4. **三、事件时间线**：`时间 | 服务端/BY | 设备端 RPA` 三列表 + **逐节点分析**（谁触发、能推出什么、**不能**推出什么、与前后节点因果）。
5. **四、影响面 · 风险 · 建议（收尾段）**：影响面（客户侧/数据侧/指标口径，给可核对数字）+ 建议表（P0 止血 → P1 防复发 → P2 复核，注明责任方与代价）。
6. **五、附件与溯源**：证据落盘表（截图相对路径）→ **复现命令**（可直接粘贴、只读）→ 数据来源清单 → 已排除/未采信（写判据）。

## HTML 十区块（结构固定，骨架 `docs/templates/final-report.html`）

① 证据落盘路径行 → ② 标题 + 元信息行（含红色状态）→ ③ 结论卡（meta 网格 + 徽标 + 红色结论条，ID 完整 32 位）→ ④ 图例（服务端蓝 / 设备端橙 / 失败点红）→ ⑤ 中心竖轴时间线（左右交替，失败点红底 ✕，卡片含证据原文）→ ⑥ 证据时间线表格（`时间 | 服务端 | 设备端`，无写 `—`）→ ⑦ 结论三段区（已证绿 / 未证候选黄 / 判别清单蓝）→ ⑧ 六源定责表（色块 + R 等级）→ ⑨ 影响面·风险·建议表（P 优先级）→ ⑩ 页脚（数据来源与复现命令 + 已排除/未采信）。

技术约束：**单文件、内联 CSS、无外链、无 JS**；`max-width:1180px` 居中；窄屏时间线退化为单列；等宽字体用于 ID/路径/日志原文。

## 硬性规则（违反即不合格）

1. **双写一致**：HTML 的结论卡 / 三段区 / 六源定责 / 影响面四项必须与 MD 的「二 / 四」**数据、结论、等级完全一致**。
2. **ID 完整 32 位**：设备 ID 与 `conversation_id` 全篇（含 HTML）不得省略或用短码。
3. **结论三段式齐备**；B 段非空时**禁止**写"根本原因是……"。
4. **六源定责齐全**，且与"影响面·风险·建议"的监控盲区项互相对得上。
5. **不留死链**：原始 json/日志按 §5.2 清除；报告中一律写"来源 + 复现命令"，不写已删文件路径。
6. **脱敏**：对外发送前去掉店铺名/会话 ID/出口 IP/`register_token` 等客户数据（内部交付照常）。

## 交付自检（提交前逐条打勾）

- [ ] 两文件都在交付目录根，命名符合规范；`证据区\screenshots\` 相对路径真实可打开
- [ ] 三段式齐备且 A 段每条有 `E#` 证据锚点
- [ ] 五段齐全，含 **D 六源定责** 与 **四、影响面·风险·建议**
- [ ] 全部 ID 完整 32 位；时间基准标注北京时间；告警时间与恢复时间分列
- [ ] HTML 自包含、可离线打开、与 MD 双写一致
- [ ] 一次性复现命令**内嵌报告**（不落脚本文件）；`证据区\` 下**只有 `screenshots\`**（无 `sls\`/`host\`/`scripts\`）
- [ ] 复现命令可直接跑通（只读）；已排除/未采信逐条有判据
- [ ] 中转区（`cs-cli\temp`、工具默认 temp）无本会话残留
