# cs-cli 排查与报告标准（强制）

> 生效日期：2026-09-24 ｜ 适用范围：本工具包（`cs-cli` / `csdbg`）下**所有**执行动作与异常查询结论（含 skill 调用、SLS/主机/截图取证、结论输出与报告交付）。
> 违反即视为无效交付。

---

## 0. 总原则

**没有实物证据，不下结论。**"实物证据"指可复现、可指认、可回放的原始载体：日志行（含时间戳/模块/函数/行号）、文件时间戳与版本字段、二进制版本信息、告警记录、进程/任务列表、截图像素、服务端记录、API 回包。推测、经验、印象、模型记忆、"通常是"——一律不算证据。

---

## 1. 结论必须三段式输出（缺一不可）

任何异常查询的结论都必须显式切成三块，**不允许把三段揉成一段"根因"**：

| 段 | 要求 | 写法约束 |
|---|---|---|
| **A. 已证部分** | 每条都挂证据（`来源 + 时间戳 + 原文片段`） | 只写证据直接支持的；涉及推断的用"→（推断）"标记并注明推断链 |
| **B. 未证候选** | 列出所有尚未被证据排除的候选机制，编号 A/B/C… | 每条写清"该候选能解释哪些观测、与哪些观测存在张力"；**禁止只留一个候选冒充结论** |
| **C. 判别性检查清单** | 每项 = 看什么 + 在哪看 + 若成立支持哪个候选 | 必须可执行、可复现；优先"不改代码就能做"的检查 |

**禁止句式**："根本原因是……"（当 B 段非空时）、"应该是/可能是/一般是……"混入 A 段、"经分析认为……"。

---

## 2. 证据必须交叉验证

1. **多源对齐（六源）**：① **服务端**（`bty-prod-ack-log/customer-servhub-api`：会话/消息/状态机/去重/转发）② **agent**（智能体层：SOP 引擎、模型服务、知识/策略、生成耗时）③ **RPA**（客户端层：UIA/CV 驱动、收发通道、本地调度与自愈）④ **host/IP**（主机与云桌面：进程/功耗/CPU/内存/磁盘、出口 IP 与网络链路）⑤ **渠道平台**（京东咚咚 / 抖音飞鸽 / 拼多多 / 千牛：平台侧渲染、口径、限流、黑名单、转接规则）⑥ **运维服务**（ops 变更记录、监控告警与工单、发布/配置）。任缺其一，要在报告里显式标注"该源缺位"并写成数据缺口建议。
2. **同一事实至少两个独立源**：例如"版本从 2.1.0 变 2.1.1"需同时有 ① 服务端记录字段 ② 主机 `version.json`/exe 文件版本 ③ 截图水印。
3. **用户提供的一切证据都要逐条利用**：截图要**逐字符放大**核对关键字段（账号名大小写、空格、全半角、时间、版本号），不能按平台记录"默认"同一写法。案例教训：某次排查中账号名在 12% 缩放下 `AI` 与 `ai` 不可辨，按平台记录"默认"写法导致漏判真实条件。
4. **口径/时间基准先对齐**：SLS `__time__` 已是北京时间、不要再 +8h；服务端 `asctime` 与 RPA 日志时间必须逐秒对齐后再下时序结论；告警时间 ≠ 恢复时间（要分别标注）。
5. **冲突即报**：两源矛盾时不选"看起来更合理的那条"，而是并列写出冲突点并给判别方法。

## 5. 执行纪律（省 token）

1. **不做无效重复请求**：同一时间窗/同一关键词的查询只发一次；需要更细时缩窗或换源，不重发原查询。
2. **先聚合后明细**：先用 SLS SQL `group by` 定范围（单机 vs 全渠道），再对少数目标拉明细。
3. **全文检索注意中文分词**：连续中文是整 token（`失败` 查不到 `登录执行失败`）；子串语义一律用 SQL `LIKE`。
4. **主机侧取证先探路后定点**：先列目录/取版本，再定点 `Select-String` 按时间前缀过滤；ECD RunCommand 输出有 24KB 截断，拆成多轮小查询。
5. **结论不重复推演**：已在下文确认过的事实不再复述推理过程，直接引用证据编号（如 `[E12]`）。

## 5.1 报告落盘位置（强制）

> 2026-09-25 修订一：报告交付区由 `D:\tmp`（平铺）改为 `D:\temp\<客服账号名>\`（按客服账号一目录）；
> 证据区由 `cs-cli\temp\<case>\` 迁入 `<客服账号名>\证据区\`，且**原始 json/日志结案后自动清除**。
> 2026-09-25 修订二（收口）：**`证据区\` 只保留 `screenshots\`**；`host\` / `scripts\` / `sls\` 三个子目录**一律不创建、出现即删**，
> 复现一律靠报告内嵌的"来源 + 复现命令"，不靠留存脚本或原始 dump。

**三区互不越界：报告进交付区、脚本进工具区、原始证据进证据区。**

### A. 交付区 `D:\temp\<客服账号名>\` —— 报告 + 证据区

- **先校验再建**：先看 `D:\temp` 是否存在，不存在则新建；再看 `D:\temp\<客服账号名>\`——**已存在直接写入，不存在才创建**（`mkdir` 幂等，不得重复建目录）。
- **`<客服账号名>`** 取本次排查命中的客服子账号昵称（`client_username` / assistant 昵称，如 `某旗舰店-客服A`、`客服小美`）；无法归属到具体账号时（平台级/设备级/跨账号问题）改用 `<渠道>-<店铺简称>` 或 `<渠道>-<设备简称>`。
- 目录结构（报告与证据同在一处，按账号检索）：

```
D:\temp\<客服账号名>\
├── YYYYMMDD-<渠道>-<账号或设备简称>-<问题简称>_FINAL_REPORT.md   # 标准框架最终报告（四段 + 影响面·风险·建议收尾）
├── YYYYMMDD-<渠道>-<账号或设备简称>-<问题简称>_report.html      # 单文件自包含网页版（必备）
├── YYYYMMDD-<主题>_<类型>报告.md                                # 必须的辅助佐证报告（专项子报告等）

  一次性复现脚本改为**以命令块/代码块内嵌进报告「五、附件与溯源」**，不再单独存文件。

- **报告类**（`_report.html` 必备）与**必须的辅助佐证报告**都放账号目录根，同一次分析不再另开目录；
- **截图**保留在 `证据区\screenshots\`（属 `<客服账号名>` 文件夹内），是本目录唯一留存物；
- 同名文件先比对再决定覆盖或加序号，禁止静默覆盖他人报告。

### B. 工具区 `cs-cli\` —— 脚本与规范，保证可维护

- **排查中新增的分析脚本一律留在 cs-cli 项目内，禁止落进交付区 `D:\temp`**：
  - 可复用工具类（后续案件继续用）→ `cs-cli\scripts\`，脚本头部注明用途/用法，并在 README 工具清单登记；
  - 一次性复现脚本（只为证明本案结论）→ **不落文件**：把关键命令/步骤**内嵌进报告「五、附件与溯源」**（必要时用代码块贴片段），报告即证据载体。
- 规范/约束类：`docs/*.md`（含本文件的修订）、`CONTRIBUTING.md`、PRD 等；工具/依赖类：`cli/`、`skill/`、`templates/`、`tests/`、`requirements*.txt`、`*_package.ps1`——一律留项目内，不得外移。
- `cs-cli\temp\` 只是排查过程中的**临时中转区**，结案必须清零（只留 `README.md`），正式产物一律按本节的交付区/工具区归位。

## 5.2 证据产物落盘（强制）

排查全程**要留存**的证据只有截图，统一归到交付区 `D:\temp\<客服账号名>\证据区\screenshots\`；
其余原始产物只在 `cs-cli\temp\` 中转，**结案必须清零**。

### ① 结案（结论交付）后自动清理

清理顺序固定为**先归集 → 再核对 → 后删除 → 收口**，四步缺一不可：

1. **归集**：截图（含放大件、裁切产物）→ `<客服账号名>\证据区\screenshots\`；报告类 → 账号目录根。散落在工具默认 temp（`~/.csdbg/temp`、其它工具项目 temp）的本会话文件一并归入。
2. **核对**：报告（md 与 html 两处）已内嵌**关键证据原文**（时间戳 + 来源 + 原文片段）与**复现命令**（project/logstore、query、时间窗）；报告引用的截图相对路径真实存在。
3. **删除**：`cs-cli\temp\` 中转残留清零（只留 README）；工具默认 temp 里本会话产生的散落文件删除（其它案件/其它会话的文件一律不碰）。
4. **收口**：`<客服账号名>\证据区\` 下**只允许存在 `screenshots\`**；若历史案件遗留 `host\` / `scripts\` / `sls\`（含空目录），一并删除。

- **为什么不留原始 dump / 脚本 / 主机原文**：大体积 json 靠**复现命令**即可重拉；脚本靠报告内嵌命令即可重跑；结论的实物证据必须在删除前落进报告正文（这也是"没有实物证据不下结论"的落点）。
- **不留死链**：报告里对原始数据的引用一律写成"来源 + 复现命令"，不写已删文件路径；确需说明时写"原始 dump 已按规范清除，可用上述命令复现"。
- **保留项**：报告（md/html）、辅助佐证报告、`证据区\screenshots\`（**仅此三者**）。

### ② 留存内容的纪律

- **脱敏**：留存的自包含 HTML、截图、脚本若含客户数据（店铺名、会话 ID、出口 IP、`register_token`/`access_key`/`inner-token`），仅限内部使用，外发前先脱敏。
- **脚本归属分清**：后续还要用的分析工具固化到 `cs-cli\scripts\`（工具区，见 §5.1 B）；只为本案的一次性复现，**写进报告命令块即可**，不落脚本文件。
- **报告与证据对得上**：核实与清理完成后，回头同步报告（md 与 html 两处）里的路径描述，确保引用即所得。
